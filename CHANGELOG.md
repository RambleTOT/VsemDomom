### S09. Акт без исполнителя — 28.09.2026
- «Я сообщил в АДС» после «Нет» ставит таймер срока проверки по норме `check_visit` (Правила № 354, п. 108). Срок истёк, а УК после повторного сообщения не отмечала «Устранено» — житель получает в личку предложение акта: срок и число потребителей из таблицы норм с основаниями, «Я готов подписать», «Как составить акт» (экран S09).
- «Я готов подписать» и «Познакомить с соседями» — в личке и через `POST /incidents/{id}/act/ready`. Знакомство только по согласию каждого: когда согласившихся двое и больше, бот присылает в личку упоминания профилей MAX (`max://user/<id>`); имена и контакты не хранятся. Отказ от готовности снимает согласие; событие `act_ready` в хронологии.
- Блок `act` в карточке аварии (`GET /incidents/{id}`, U02): доступность, срок проверки, сколько нужно и сколько готовы. В инструкции «Воды нет — что делать» — кнопка «Как составить акт». Всё — только при `FEATURE_ACT_TEMPLATE`.

  - тестовые токены не меняют и не удаляют профиль песочницы (403);
  - ПДн: номер заявки, похожий на телефон, не принимается (`ads_number_invalid`); из лички в очередь попадают только команды и короткий ввод с цифрами; в логах — шаблон маршрута без токенов из ссылок и без IP, ошибки без параметров SQL; `/ready` без текста ошибок;

- `POST /uk/houses/{id}/demo/reset`: аварии, созданные при проверке, удаляются вместе с отметками, хронологией и сроками, неотправленные сообщения по ним отменяются; история дома пересоздаётся в текущем месяце, как после сидов (`SEEDS_DIR`); панель дома правится. - `audit_log` заполняется: действия УК (статус, объединение, привязка чата) и демо-инструменты — кто, что, над чем, без ПДн.

### A8. Проверка после «Устранено», расхождение, закрытие, итог — 27.09.2026
- Ответы на вопрос о восстановлении (C03) в чате и `POST /incidents/{id}/observations`: «Да» / «Нет» / «плохая», действует последний; ответивший становится участником; нажатие в чате дома подтверждает уровень 1. Время восстановления для квартиры — ядро (`applyRestoredAnswer`): после «Нет» — время подтверждения, иначе отметка УК.

### A7. Действия УК, таймеры сроков, личные уведомления — 27.09.2026
- `POST /uk/incidents/{id}/status`: переход и эффекты задаёт машина состояний ядра, сервис исполняет их в одной транзакции — ориентир, сроки «выполнено / истёк» (в том числе единовременный лимит при «Устранено»), пропущенные шаги в хронологии, версия +1; `If-Match` → 409 `version_conflict` с `currentVersion`; недопустимый переход → 409 `invalid_transition`; «Принято» без ориентира или с прошедшим ориентиром → 422. Ответ не ждёт MAX: карточка, вопрос и уведомления — в очереди.
- «Устранено»: `checking`, вопрос о восстановлении C03 — второе новое сообщение в чат (в бюджете трёх); повторное «Устранено» после расхождения правит тот же вопрос («Повторная проверка»). В песочнице — сразу `closed` без сообщений.
- Объединение дублей (`…/merge`): участники переносятся в актуальную аварию, сроки дубля отменяются, обе карточки правятся.
- Таймеры сроков F04 (очередь `deadline-tick`): «до срока 30 минут» (кроме сроков короче окна предупреждения) и «срок истёк» — событие, флаг `overdue` / `single_limit_exceeded`, правка карточки; задача сверяется с пересчитанным сроком (номер АДС) и ставит себя заново.
- Личные уведомления присоединившимся (очередь `notify-participants`): смена статуса УК и сроки, нейтральным текстом; только тем, у кого включено «Уведомлять меня» и начат диалог; «Не присылать» выключает уведомления по аварии; по умолчанию — из настроек профиля.
- Экраны УК в REST: аварии своих домов (срок истёк → подходит → новые → остальные; счётчики; дома), авария с сеткой «подъезд × этаж», жителями, действиями и кандидатами на объединение; дома с чатом и правами бота, итог месяца (U06), демо-блок для демо-роли; привязка чата по токену `c_` (410 для использованного или устаревшего).
- Исправлено: `lowerFirst` не меняет аббревиатуры («УК сообщит сроки работ»).

### A6. REST API жителя: вход, профиль, дома, нормы, аварии — 27.09.2026
- Вход по `initData` MAX строго по алгоритму dev.max.ru (пары через «&», каждый ключ один раз, `decodeURIComponent`, HMAC-SHA256 с ключом `WebAppData`, сравнение за постоянное время, `auth_date` не старше часа ± 60 с); из initData берутся только ID пользователя, язык, чат и `start_param` — имя и фамилия не сохраняются.
- Сессия JWT (HS256, `SESSION_SECRET`) на 12 часов; роли и проживание читаются из БД на каждый запрос; истёкшая — 401 `session_expired`. Dev-вход `POST /auth/dev` только при `DEV_AUTH=true` (сотрудник — демо-роль модельной УК). Checker-токены — только при `CHECKER_API_ENABLED` и только для дома-песочницы.
- Эндпоинты регистрируются по контракту `packages/shared` (метод, путь, zod-схемы параметров, запроса и тела → 400 `validation_error`); вне production ответ сверяется со схемой; флаги функций → 404 `feature_disabled`; тест сверяет зарегистрированные операции со списком запланированных по задачам.
- Лимиты `@fastify/rate-limit`: 60 запросов в минуту на пользователя, 10 на вход с одного IP; 429 `rate_limited` в формате problem+json.
- Профиль: `GET /me`, согласие с версией, проживание (общий сервис с регистрацией в личке: смена квартиры сбрасывает доверие, проверка членства в чате), `DELETE /me`, настройки уведомлений.
- Дома: поиск (песочница — только проверяющим), краткие сведения, главная жителя (активные аварии, последние итоги, месяц по квартире против лимита), `…/month` с интервалами, единовременным и месячным лимитами и основаниями.
- Нормы: действующие сегодня, по услуге и общие, федеральные и региональные, с основаниями.
- Аварии жителя: создание (`Idempotency-Key`, 409 `duplicate_incident` с `duplicateOf`, 422 для времени в будущем и старше суток без подтверждения), подробности (сроки с основаниями и точкой отсчёта, счётчики, шаги статусов с пропущенными, хронология, моё участие, АДС, проверка), «У меня тоже» с подъездом и этажом (`joined` / `already_joined` / `updated`), «Не у меня», номер заявки АДС и «не дозвонился», «Уведомлять меня». «Только в моей квартире» видна автору и УК.
- `If-Match` (разбор и 409 `version_conflict`) — для статусов УК в A7.
- Миграция `0001`: публичный ID у проживания (`residency.public_id`).

### A5. Сообщение об аварии в личке, живая карточка, подъезды — 27.09.2026
